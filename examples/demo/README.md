# Valor demo profile

A seeded, entirely fictional Valor profile for demoing all eleven workflows —
with no access to your real work.

The trick is that the mock is in the **inputs**, not the outputs. A slide deck
fakes what Valor produces; this fakes what Valor reads. Every briefing, review,
reflection and coaching footer you show is generated by Valor's real prompts and
real CLI, over invented tickets, PRs, meetings and evidence.

## Why a separate HOME

Valor resolves its state through `Path.home()`, so pointing `HOME` at a scratch
directory gives the demo a complete parallel universe: its own
`career_framework.md`, `state.json`, evidence database, and agent config. Your
real `~/.valor` isn't hidden from the demo — the process can't reach it. No
scrubbing, no screen-share luck.

## Setup

From the repo root:

```bash
HOME=~/valor-demo bash install.sh
```

```bash
python3 examples/demo/seed.py ~/valor-demo
```

```bash
HOME=~/valor-demo claude
```

Order matters: the installer writes the demo home's `CLAUDE.md`, and the seeder
appends the demo-mode block to it. `seed.py` refuses to run against your real
home, and refuses to overwrite an existing profile without `--force`.

Then follow **[DEMO.md](DEMO.md)** — a ~20-minute run-book covering all eleven
commands plus ambient coaching, with timings, what to say, and fallbacks.

Re-seed the morning of the demo (dates are relative to the seed date):

```bash
python3 examples/demo/seed.py ~/valor-demo --force
```

Teardown:

```bash
rm -rf ~/valor-demo
```

## What gets seeded

| Piece | Detail |
|---|---|
| Career framework | The generic IC ladder from [`examples/frameworks/`](../frameworks/), L3 → L4, ceiling L5 |
| Evidence store | ~50 entries over the last six months, all five competencies, with `status` / `role` / `value` tags |
| Weekly summaries | Three past weeks, so 1:1 prep and the reflection build on prior reflections |
| Open claims | Two, so the verification gate has something real to check on the first briefing |
| Carry-forward | Yesterday's wrap-up note, so the briefing has something to carry |
| Fixtures | Jira, GitHub, a full PR (metadata + diff), calendar, meeting notes, a running 1:1 doc, news, local git activity |
| State | All four integrations **off**, calendar writes **off**, update checks pinned |

The persona: Alex, a software engineer at L3 targeting L4 on a checkout/payments
team. Manager Sam; teammates Riley, Jordan, Dana; project key `PROJ`; repos under
`example-org`. Nothing here corresponds to a real company, person, or system.

## How the fixtures reach the commands

`seed.py` renders `fixtures/` into `~/.valor/demo/` (resolving `{{TODAY}}`-style
date tokens so the calendar is always current) and installs
[`demo-mode.md`](demo-mode.md) into the demo home's `CLAUDE.md`. That block tells
the agent to read those files wherever a command's spec would call GitHub, Jira,
the calendar, news, or git — and forbids writing to any external system.

Everything else runs for real: the evidence CLI, verification gate, day planner,
project-focus resolver, coaching, and the review-console generator.

## Deliberate demo hooks

The data is seeded so the features that look like magic have something to find:

- **A merged PR with no evidence entry** (#397) — `/valor-reflection`'s coverage
  check catches work you forgot to log
- **A deliverable with no `role`** — the confirm-before-you-submit list asks
  whether you led or co-built it
- **An `in_progress` fix that reads like it shipped** — the reflection must phrase
  it from the recorded status, not the optimistic prose
- **Almost no industry-knowledge signal** — the weekly gap analysis has a real gap
- **A blocked downstream ticket** (PROJ-248 waiting on #418) — the briefing's
  dependency rules change the day's order
- **A claim asserted "not sent"** — the verification gate checks before re-raising
- **A manager commitment that wasn't delivered** — upward feedback grounded in
  observed behavior

## Editing it

The fixtures are plain JSON and Markdown; change the persona, the stack, or the
ladder to suit your audience. Date tokens available anywhere in a fixture:
`{{TODAY}}`, `{{TODAY-7}}`, `{{TODAY+1}}`, `{{MONDAY}}`, `{{LAST_MONDAY}}`,
`{{CYCLE_START}}`, `{{CYCLE_START+34}}`, `{{TZ}}`, `{{YEAR}}`.

If you demo in Codex CLI or Cursor instead, install with
`--target codex` / `--target cursor` and put the demo-mode block in that host's
rule file (`~/.codex/AGENTS.md` or `~/.cursor/rules/`) — `seed.py` writes the
Claude Code one.
